# Playgrounds

Status: **CONCEPT catalog boundary; no GUI or playground implementation**.

Playgrounds let people observe, understand, experiment, compare, return when
possible, modify, and try again through underlying engine contracts. An interface
must explain whether it is inspecting, simulating, proposing, or changing live
state. It must not duplicate engineering logic or conceal recovery limits.

Future entries should identify their engine contract, intended audience, visible
evidence and unknowns, actions and authority, preview/simulation limits,
comparison behavior, recovery semantics, accessibility, and validation.

Start from [PLAYGROUND_LAW](../docs/PLAYGROUND_LAW.md) and
[PLAYGROUND_CONTRACT](../docs/PLAYGROUND_CONTRACT.md). The
[generator concept](../docs/PLAYGROUND_GENERATOR.md) may eventually reduce
repetitive UI work; it is not a current capability or a requirement to generate
every domain interface automatically.
