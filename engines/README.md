# Engines

Status: **CONCEPT catalog boundary; no engine implementations**.

An engine owns one coherent engineering capability and exposes facts, diagnosis,
plans, and verified outcomes through the proposed
[engine contract](../docs/ENGINE_CONTRACT.md). Keep its core independent of GUI
technology. Important suitable capabilities should have a human playground using
the same authoritative semantics as their AI interface.

Codex, Windows, runtimes, GPU, CAD, Git, and specialist integration engines are
possible future entries, not empty modules to generate now. Introduce an engine
only after a real requirement establishes its scope and evidence.

A future entry should document purpose, status, inputs/outputs, permissions,
dependencies, supported and tested environments, evidence, human surface,
verification, recovery limits, and focused tests. A name in this catalog must
never imply installed capability or supported software.
